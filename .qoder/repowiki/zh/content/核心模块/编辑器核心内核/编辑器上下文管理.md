## 核心组件
- 应用上下文（AppContext）
  - 提供插件管理器实例，作为应用级共享对象注入到组件树中
  - 便于跨页面、跨功能模块访问插件能力
- 页面上下文（PageContext）
  - 传递页面元信息（如空间 ID、页面 ID、标题、创建者等），用于渲染侧边目录、面包屑、权限控制等
- 编辑器提供者（EditorProvider）
  - 定义用户信息、文件上传下载等外部能力接口，由宿主环境注入到编辑器中
- 渲染器（EditorRender / CollaborationEditor）
  - 负责创建编辑器实例、挂载内容、渲染目录、提供主题与样式
  - 在根部以 Provider 形式注入 PageContext 与主题上下文
- 属性订阅钩子（use-attributes）
  - 订阅编辑器选区或事务变化，按需更新组件状态，避免全量重渲染
- 扩展事件（EventExtension）
  - 为编辑器扩展注入统一事件发射器，支持扩展间解耦通信
- 事件总线（EventEmitter）
  - 提供 on/emit/off/destroy 等基础能力，支撑应用级事件传播
- **新增** 协作状态管理
  - 通过 Awareness 机制跟踪在线用户状态
  - 实现用户意识更新和协作状态同步

## 架构总览
编辑器上下文管理通过"上下文 + 钩子 + 事件 + 协作状态"的组合实现：
- 上下文：PageContext 注入页面元信息；AppContext 注入插件管理器
- 钩子：use-attributes 基于编辑器事件驱动组件状态更新
- 事件：EventExtension 暴露统一事件发射器；EventEmitter 支撑应用级事件广播
- **新增** 协作状态：Awareness 机制跟踪在线用户，实现实时协作状态同步

## 详细组件分析

### 页面上下文（PageContext）与渲染系统
- 设计目的
  - 将页面元信息（空间、页面、标题、创建者等）以 React Context 的形式向下传递，供目录、菜单、权限判断等组件使用
- 实现要点
  - 渲染器在根部以 Provider 包裹，将 pageInfo 作为上下文值注入
  - 渲染器同时负责主题与样式注入，确保编辑器区域具备一致的视觉表现
- 数据流
  - 宿主页面准备 pageInfo，渲染器接收后注入上下文
  - 子组件通过 useContext 读取上下文，结合 use-attributes 订阅编辑器状态，实现联动更新

### 编辑器提供者（EditorProvider）与用户/文件能力
- 设计目的

### 属性订阅与组件通信（use-attributes）
- 设计目的
  - 将编辑器内部状态（如选区、节点属性）映射为组件可感知的状态，减少不必要的重渲染
- 工作原理
  - 订阅编辑器的 selectionUpdate 与 transaction 事件
  - 合并默认值与当前属性，使用深比较避免重复更新
  - 通过回调将最新值回传给宿主或上层组件
- 性能影响
  - 仅在属性变化且与缓存值不相等时更新，降低渲染成本

```mermaid
flowchart TD
Init(["初始化订阅"]) --> Listen["监听 selectionUpdate/transaction"]
Listen --> Compute["合并默认值与当前属性"]
Compute --> Compare{"与缓存值相等？"}
Compare -- 是 --> Idle["保持不变"]
Compare -- 否 --> Update["更新状态并缓存"]
Update --> Notify["触发回调/通知上层"]
Notify --> Listen
```

### 扩展事件与应用级事件传播
- 扩展事件（EventExtension）
  - 为编辑器扩展注入统一事件发射器，扩展之间可通过该发射器进行低耦合通信
- 应用级事件（EventEmitter）
  - 提供 on/emit/off/destroy 方法，支持应用内事件广播与清理
- 集成方式
  - 在渲染器中引入 EventExtension，使其成为编辑器扩展的一部分
  - 通过宿主页面或业务逻辑调用 emit 触发事件，订阅方响应处理

### 插件管理与上下文生态

## 协作状态管理

### Awareness 机制概述
协作状态管理通过 Awareness 机制实现用户意识更新，确保所有协作者能够实时看到彼此的在线状态。

- **设计目的**
  - 跟踪在线用户的光标位置、选区状态和用户信息
  - 实现实时协作状态同步，提升多人协作体验
  - 提供用户列表展示和连接状态指示

- **核心组件**
  - **Awareness 对象**：管理用户状态的 Yjs Awareness 实例
  - **onAwarenessUpdate 回调**：监听用户状态变化
  - **用户状态过滤**：过滤掉无用户信息的状态条目
  - **深度比较优化**：使用 deepEqual 避免重复渲染

### 用户意识更新流程

```mermaid
sequenceDiagram
participant Client as "客户端"
participant Awareness as "Awareness实例"
participant Callback as "onAwarenessUpdate回调"
participant State as "状态管理"
participant UI as "用户界面"
Client->>Awareness : 初始化Awareness
Awareness->>Client : 用户加入/离开
Awareness->>Callback : 触发状态更新
Callback->>State : 过滤用户状态
State->>State : 深度比较更新
State->>UI : 更新用户列表
UI->>Client : 显示协作状态
```

### 协作状态管理最佳实践

- **状态过滤**
  - 使用 `.filter(u => u.user)` 过滤掉无用户信息的状态条目

- **内存管理**
  - 在组件卸载时销毁 Awareness 实例
  - 断开协作连接，释放相关资源

## 用户信息管理

### 用户信息结构设计
用户信息管理是协作状态的核心组成部分，负责为每个协作者提供唯一的身份标识和视觉表示。

- **用户信息字段**
  - `id`: 用户唯一标识符（支持字符串和数字）
  - `name`: 用户显示名称
  - `avatar`: 用户头像URL（可选）
  - `color`: 用户专用颜色，用于协作光标和头像标识

- **颜色生成算法**
  - 基于用户ID的哈希算法生成稳定的颜色
  - 使用预定义的颜色数组，确保颜色分布均匀
  - 支持匿名用户的默认颜色分配

### 用户信息生成流程

```mermaid
flowchart TD
Start(["开始生成用户信息"]) --> CheckID{"检查用户ID"}
CheckID -- 有ID --> Hash["计算ID哈希值"]
CheckID -- 无ID --> UseName["使用用户名作为标识"]
Hash --> CalcColor["计算颜色索引"]
UseName --> CalcColor
CalcColor --> GetColor["从颜色数组获取颜色"]
GetColor --> CreateUser["创建用户对象"]
CreateUser --> End(["返回用户信息"])
```

## 性能考量
- 事件驱动的细粒度更新
  - 使用 use-attributes 订阅编辑器事件，避免全量重渲染
- 合并扩展与内容
  - 渲染器在创建编辑器时合并扩展与内容，减少重复计算
- 主题与样式注入
  - 通过 ThemeProvider 与样式模块化，避免样式抖动与重复渲染
- 协作编辑生命周期管理
  - 在销毁时断开协作连接，释放资源，避免内存泄漏
- **新增** Awareness 优化
  - 使用 lastAwarenessRef 缓存用户状态，避免重复渲染
  - 通过 deepEqual 进行状态比较，只有当状态真正改变时才更新
  - 合理的用户状态过滤，减少不必要的状态处理

## 故障排查指南
- 上下文未生效
  - 检查是否在渲染器根部注入了 PageContext
  - 确认 pageInfo 是否正确传入
- 事件未触发
  - 确认 EventExtension 已被添加到编辑器扩展集合
  - 检查 EventEmitter 的 on/emit 调用链路
- 协作编辑无法连接
  - 检查 Provider 的初始化参数与生命周期
  - 确认销毁流程中执行了断开与销毁
- 属性订阅无效
  - 确认编辑器事件（selectionUpdate/transaction）是否正常触发
  - 检查默认值与当前属性合并逻辑
- **新增** 协作状态问题
  - 检查 Awareness 实例是否正确初始化
  - 确认 onAwarenessUpdate 回调是否正常触发
  - 验证用户状态过滤逻辑是否正确
  - 检查 deepEqual 比较是否正常工作

## 结论
编辑器上下文管理系统通过"上下文 + 钩子 + 事件 + 协作状态"实现了清晰的分层与解耦：
- PageContext 与 EditorProvider 提供稳定的运行时依赖
- use-attributes 将编辑器状态转化为组件可控的状态
- EventExtension 与 EventEmitter 为扩展与应用提供事件通信通道
- **新增** Awareness 机制实现用户意识更新，完善协作状态管理
- 渲染器与协作编辑器在统一入口注入上下文与主题，保证一致性与可维护性
