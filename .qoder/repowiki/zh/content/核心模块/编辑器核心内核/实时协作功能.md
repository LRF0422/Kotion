## 简介
本技术文档聚焦于编辑器的实时协作能力，围绕以下目标展开：
- 解释 Yjs 协作协议与基于 Yjs 的协同模型在本项目中的落地方式（通过 @hocuspocus/provider 与 @hocuspocus/server）。
- 阐述room-server包作为协作服务器的集成方式：连接建立、文档同步、持久化与广播、用户状态（Awareness）管理。
- 说明协作提供者（Provider）的配置与使用：服务器地址、认证令牌、事件回调、断线重连策略等。
- 提供协作编辑的用户体验设计建议：光标同步、用户颜色标识、在线状态显示。
- 给出可直接参考的代码片段路径，帮助快速定位实现细节。
- 完善环境配置与部署文档，支持多环境协作服务器URL管理。

**更新** 本版本更新了协作服务器架构，采用Nginx反向代理和SSL终止，WebSocket URL从ws://kotion.top:1234更新为wss://kotion.top:8877/ws，提供更安全可靠的实时协作解决方案。

## 项目结构
本项目的实时协作由"前端编辑器 + room-server协作服务 + 数据存储 + 消息中心"四层组成：
- 前端编辑器层：基于 Tiptap 与 Yjs 的协作编辑器组件，负责渲染、扩展加载、事件处理与 Provider 生命周期管理。
- 协作服务层：room-server包提供的Hocuspocus服务器，负责WebSocket连接、文档分发、状态广播、扩展集成。
- 存储层：MySQL/SQLite/Redis 等，用于持久化文档快照与跨节点同步。
- 消息中心层：WebSocket 实时通信系统，支持协作邀请通知、消息推送和状态跟踪。

## 核心组件
- 协作编辑器组件：封装编辑器实例、扩展加载、工具栏、目录等 UI 结构，并通过 Provider 管理协作生命周期。
- 协作提供者（Provider）：封装与room-server的连接、文档同步、Awareness 状态更新、连接状态回调。
- room-server包：全新的协作服务器实现，基于Hocuspocus框架，提供模块化的扩展支持和Docker容器化部署。
- MySQL插件：重构后的数据库扩展，采用Mysql类继承Database基类，提供更好的错误处理和连接管理。
- 即时消息系统：基于 WebSocket 的实时通信，支持消息发送、接收、状态跟踪和自动重连。
- 协作邀请系统：完整的邀请流程管理，包括邀请创建、验证、接受和消息中心通知。
- 外部插件加载：动态加载协作方的编辑器插件，确保一致的编辑体验。
- 环境配置管理：统一的环境变量配置，支持多环境协作服务器URL管理。
- Nginx反向代理：提供SSL终止、WebSocket升级和负载均衡支持。

**更新** 新增Nginx反向代理支持，提供SSL加密和WebSocket升级功能，增强协作服务器的安全性和可靠性。

### 协作提供者（Provider）配置与使用
- 服务器地址与文档命名空间：通过 baseUrl 与 name 指定协作房间；每个文档名对应一个独立的 Y.Doc。
- 认证与令牌：通过 token 字段传递认证信息，由服务器侧校验。
- 事件回调：
  - onAwarenessUpdate：订阅其他用户的 Awareness 状态，可用于渲染协作光标与在线用户列表。
  - onSynced：文档已同步，可切换 UI 状态或进行后续初始化。
  - onStatus：连接状态变化（如 connecting/synced/disconnected 等）。
- 断线与重连：Provider 内置重连机制，可在网络波动时自动恢复。
- 环境配置：支持从环境变量读取协作服务器URL，实现多环境配置管理。

**更新** 协作服务器URL现已更新为wss://kotion.top:8877/ws，采用Nginx反向代理和SSL终止，提供更安全的连接。

### MySQL插件重构实现
- 类继承架构：Mysql类继承自@hocuspocus/extension-database的Database基类。
- 连接管理：采用mysql原生驱动，提供自动重连和错误处理机制。
- 数据库操作：实现文档的拉取(fetch)和存储(store)功能，使用UPSERT语句确保数据一致性。
- 连接健康检查：定时执行ping操作，监控数据库连接状态并自动恢复。
- 配置灵活性：支持通过构造函数参数和环境变量配置数据库连接。

**更新** MySQL插件增强了连接健康检查机制，定时执行ping操作监控连接状态，提供更稳定的数据库连接管理。

## 性能考量
- 传输与映射：Yjs 的增量传输与映射机制显著降低带宽占用；在高并发场景下，建议启用 Redis 扩展以提升广播效率。
- 历史压缩：编辑器内部对历史分支进行压缩与重映射，减少内存占用与重放成本。
- UI 渲染：在大量协作光标同时出现时，建议按需渲染与节流，避免频繁重绘。
- 断线重连：Provider 默认具备重连策略，建议在业务层根据网络状态调整重试间隔与最大重试次数。
- 即时消息优化：WebSocket 连接池管理、消息队列缓冲、心跳间隔优化等措施提升实时通信性能。
- 内存管理：及时清理协作提供者资源，避免内存泄漏；合理使用 React.memo 和 useMemo 优化组件渲染。
- 外部插件加载：批量加载插件时使用Promise.allSettled，避免单个插件失败影响整体加载。
- room-server优化：采用连接池管理数据库连接，定时健康检查，自动重连机制提升服务器稳定性。
- 环境配置优化：统一的环境变量管理减少配置错误，支持多环境差异化配置。
- Nginx优化：反向代理缓存、连接池管理、SSL会话复用等措施提升WebSocket性能。

**更新** 新增Nginx性能优化建议，包括反向代理缓存、连接池管理和SSL会话复用，提升WebSocket连接性能。

## 故障排查指南
- 连接失败
  - 检查room-server端口与网络可达性；确认环境变量配置正确。
  - 查看room-server日志输出，定位连接与握手阶段问题。
  - 验证MySQL数据库连接参数和网络连通性。
  - 确认SSL证书配置正确，检查证书文件路径。
  - 验证Nginx反向代理配置，检查WebSocket升级是否正常。
- 文档未同步
  - 确认文档名称（room）一致；检查 Provider 的 onSynced 是否触发。
  - 若使用MySQL插件，确认拉取/存储逻辑正常，必要时手动校验数据库表结构。
  - 验证环境变量VITE_COLLABORATION_WS_URL配置正确。
- 光标异常
  - 检查 Awareness 回调是否被正确订阅；核对用户颜色分配逻辑。
  - 关注选择过滤插件，避免协作期间的选择覆盖导致光标错位。
- 拖拽光标错位
  - 确保文档内容变化后及时更新拖拽光标覆盖层；检查 resolve 位置是否正确。
- 即时消息问题
  - 检查 WebSocket 连接状态和心跳机制；验证认证令牌有效性。
  - 确认wss://kotion.top:888连接可用，检查SSL证书配置。
  - 查看消息发送/接收日志，确认消息类型和内容格式正确。
- 协作邀请问题
  - 检查邀请API响应状态和消息中心通知是否正常。
  - 验证邀请token格式和有效期，确认消息中心消息解析正确。

## 结论
本项目采用 Yjs + room-server 的协作方案，通过新的room-server包与服务器扩展实现低耦合、可扩展的实时协作能力。前端侧重于编辑器体验与用户状态呈现，服务器侧通过重构的MySQL插件和模块化扩展保障持久化与广播效率。配合 CRDT 的自动合并机制与本地历史映射，系统在高并发与弱网环境下仍能保持一致性与稳定性。
