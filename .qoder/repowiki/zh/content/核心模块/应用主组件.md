## 引言
本文件面向知识库管理系统的核心应用主组件，围绕 App.tsx 作为应用入口，系统性阐述其路由管理、布局系统与全局状态协调；解析 Layout 组件的侧边栏菜单、头部导航与内容区域组织；梳理路由配置（静态路由与动态路由）与菜单系统（动态生成、权限与界面适配）；并给出应用启动流程（插件初始化、用户认证、数据预加载）的完整说明。文档同时提供可视化图示与具体文件路径指引，帮助开发者快速理解与扩展。

**更新** 新增了PluginErrorBoundary组件的集成，为插件路由提供统一的错误隔离机制，确保单个插件的崩溃不会影响整个应用的稳定性。

## 项目结构
应用主组件位于 packages/core/src，采用"入口组件 + 布局 + 菜单 + 错误边界 + 引导流程 + 插件生态"的分层设计：
- 入口与路由：App.tsx 负责根据登录态与插件列表构建路由树，并注入上下文与主题/全局状态。
- 错误处理：PluginErrorBoundary 提供插件级错误隔离，ErrorPage 处理全局路由错误。
- 布局系统：Layout.tsx 提供侧边栏、主内容区与引导流程；SiderMenu.tsx 聚合插件菜单与内置功能。
- 引导流程：Welcome.tsx 提供用户首次使用引导，包含多步骤介绍和进度跟踪。
- 插件生态：PluginManager.ts 负责插件加载、合并路由/菜单/语言包与服务；AppContext.ts 提供插件管理器的全局访问。
- 认证与商店：Login/SignUp 页面负责用户认证；Shop/Marketplace/PluginDetail 管理插件市场与详情页。

## 核心组件
- App.tsx：应用入口，负责：
  - 插件管理器初始化与动态路由构建；
  - 国际化资源合并与初始化；
  - 登录态判断与路由切换；
  - 提供 AppContext 与主题/全局状态/模态等上下文。
  - **新增** 自动包装插件路由元素，提供错误隔离机制。
- PluginErrorBoundary.tsx：插件错误边界，负责：
  - 捕获插件路由组件的错误；
  - 提供页面级和内联级错误回退；
  - 支持错误重试和导航功能。
- ErrorPage.tsx：全局错误页面，负责：
  - 处理未被PluginErrorBoundary捕获的全局路由错误；
  - 提供详细的错误信息和恢复选项。
- Layout.tsx：布局容器，负责：
  - 侧边栏菜单渲染与主内容 Outlet；
  - 用户信息拉取与跳转；
  - 插件安装请求弹窗与引导流程。
- SiderMenu.tsx：侧边栏菜单，聚合插件菜单与内置功能（商店、消息、设置、用户信息），支持点击导航与下拉操作。
- Welcome.tsx：用户引导流程，提供多步骤介绍、进度跟踪和开始使用功能。
- PluginManager.ts：插件管理器，负责远程插件脚本加载、合并路由/菜单/语言包与服务，提供安装/卸载能力。
- AppContext.ts：应用上下文，向子组件暴露插件管理器实例。
- GlobalState.ts：全局状态模型，包含用户信息、应用信息、标签页与折叠状态等。
- use-navigator.ts：统一导航封装，支持带标签页附加的导航。
- api/index.ts：集中定义后端接口常量，便于调用与维护。
- event.ts：轻量事件总线，用于跨组件通信（如刷新插件列表）。

## 架构总览
应用采用"入口路由 + 动态插件 + 错误边界 + 布局容器 + 引导流程"的架构模式：
- 入口路由在 App.tsx 中根据登录态与插件列表动态生成；
- 插件通过 PluginManager 加载并合并其路由/菜单/语言包；
- **新增** PluginErrorBoundary 自动包装所有插件路由元素，提供错误隔离；
- Layout 负责侧边栏与主内容区，SiderMenu 聚合插件菜单；
- Welcome 组件提供用户首次使用引导流程；
- 全局状态由 store 提供，上下文通过 AppContext 注入；
- 认证流程由 Login/SignUp 页面完成，随后触发插件初始化与路由重建；
- **新增** ErrorPage 处理未被PluginErrorBoundary捕获的全局错误。

### App.tsx：应用入口与路由构建
- 插件初始化与动态路由：
  - 使用 PluginManager 初始化插件（本地与远程），合并插件路由配置；
  - 将插件路由与内置路由（如商店）组合为完整的路由树；

  - 提供 AppContext、ModalProvider、ThemeProvider、全局状态 Provider。

### PluginErrorBoundary.tsx：插件错误边界
- 错误隔离机制：
  - 捕获插件路由组件的错误，防止单个插件崩溃影响整个应用；
  - 支持两种回退模式：页面级（preserve sidebar/navigation）和内联级（node views）。
- 用户体验：
  - 提供清晰的错误信息和重试按钮；
  - 支持返回上一页和重试功能；
  - 内联模式下提供简洁的错误卡片。
- 日志记录：
  - 捕获错误时记录详细的错误信息和组件信息；
  - 便于调试和问题追踪。

**新增** 作为应用错误处理体系的核心组件，提供了一致的插件错误隔离机制。

## 性能考虑
- 插件加载：
  - 使用 importScript 按需加载远程插件脚本，避免首屏体积膨胀；
  - 合并语言包与服务时注意去重与增量更新。
- 路由构建：
  - 动态路由树仅在插件初始化完成后构建，减少无效渲染；
  - 子路由按需懒加载，结合 Outlet 实现。
  - **新增** PluginErrorBoundary 的包装是纯函数式操作，不影响渲染性能。
- UI 与状态：
  - 使用 useSafeState 与 useMemo 降低重渲染；
  - 全局状态按模块拆分，避免大对象全量替换。
- 引导流程：
  - Welcome 组件使用动画和渐变效果，注意在移动设备上的性能表现。
- **新增** 错误边界性能：
  - PluginErrorBoundary 使用 React 的 getDerivedStateFromError，性能开销最小；
  - 错误状态仅在插件组件抛错时激活，正常情况下零开销。

## 故障排查指南
- 登录后无法进入首页：
  - 检查 REFRESH_PLUSINS 是否正确触发与监听；
  - 确认 PLUGIN_INIT_SUCCESS 是否在登录成功后发出。
- 插件菜单不显示：
  - 确认 PluginManager 初始化是否成功；
  - 检查插件是否正确导出 menus 字段。
- 国际化资源缺失：
  - 确认 resloveLocales 合并逻辑与 i18n 初始化参数；
  - 检查插件语言包命名与键值。
- 用户信息拉取失败：
  - 检查 GET_USER_INFO 接口与 token 有效性；
  - 确保未登录时跳转到登录页的逻辑生效。
- Welcome 引导流程异常：
  - 检查 localStorage 中的 hasCompletedWelcome 标记；
  - 确认路由配置中的/welcome路径正确。
- **新增** 插件路由错误：
  - 检查 PluginErrorBoundary 是否正确包装插件路由元素；
  - 确认插件组件是否正确处理错误边界；
  - 查看浏览器控制台中的错误日志。
- **新增** 全局路由错误：
  - 检查 ErrorPage 是否正确处理未捕获的错误；
  - 确认路由配置中的 errorElement 设置。

## 结论
