## 简介
本文件面向知识库管理系统的生产部署与运维，覆盖多种部署形态，包括传统的 Web 应用部署、新增的 Electron 桌面应用部署，以及独立的协作编辑服务部署。内容涵盖容器化、反向代理、环境变量、多场景部署（云服务器、容器集群、本地开发）、CI/CD 流程、性能优化（缓存、静态资源、数据库连接池）、安全加固（HTTPS、访问控制、数据加密）以及监控与故障排除建议。基于仓库中现有的配置文件与脚本进行归纳总结，并提供可操作的落地步骤。

**更新** 新增独立的 Electron 桌面应用部署配置，提供桌面应用特有的构建配置、自定义协议处理和打包流程。更新应用架构图，展示桌面应用与 Web 应用的协同部署模式。

## 项目结构

## 核心组件
- **Electron 桌面应用**：基于 Electron 的跨平台桌面应用，支持自定义协议处理、IPC 通信和本地数据存储，提供离线优先的用户体验。
- 协作编辑服务：基于 Hocuspocus 的服务端，支持 MySQL 与 Redis 扩展，通过环境变量配置数据库与缓存。

- Nginx 反向代理：统一暴露 80/443 端口，转发 /api 到后端服务，支持 WebSocket 升级与静态资源。
- 前端应用：
  - Vite 应用：本地开发时通过代理将 /api 请求转发至 Nginx 暴露的服务。
  - Next.js 应用：生产构建输出独立可运行包，配合 Dockerfile 运行。
- 工具链：Turbo 统一构建、缓存与任务依赖；pnpm workspace 管理多包。

**更新** 新增 Electron 桌面应用的核心组件说明，包括自定义协议处理、IPC 通信和本地数据存储功能。更新协作编辑服务和独立 room-server 的部署选项。

## 架构总览

## 详细组件分析

### Electron 桌面应用
- **功能特性**：
  - 自定义协议处理：注册 app:// 协议，支持 SPA 路由和本地资源访问
  - IPC 通信：通过 contextBridge 暴露安全的 API 给渲染进程
  - 本地数据存储：使用 better-sqlite3 和 SQLite 数据库
  - 离线优先：匿名用户无需登录即可使用，数据保存在本地
  - 三层认证：支持匿名用户、注册用户和会员三种身份
- **构建配置**：
  - 使用 electron-vite 进行开发和构建，支持主进程、预加载脚本和渲染进程的独立配置
  - TypeScript 配置分为 node 环境和 web 环境两套配置
  - Tailwind CSS 和 PostCSS 配置继承自 UI 包
- **打包流程**：
  - 支持多平台打包：Windows (NSIS/ZIP)、macOS (DMG/ZIP)、Linux (AppImage/DEB)
  - 使用 electron-builder 进行最终打包，配置应用元数据和安装程序选项

**更新** 新增 Electron 桌面应用的详细配置说明，包括自定义协议处理、IPC 通信和打包流程。

### Nginx 反向代理
- 静态资源：映射前端构建产物目录，支持 index 回退与单页路由。
- API 反代：将 /api 前缀转发至后端服务地址，保留 Host、X-Real-IP、X-Forwarded-For 头，启用 WebSocket 升级。
- 安全与性能：开启 gzip、限制上传大小、设置 keepalive 超时、错误页面映射。
- HTTPS：加载证书与私钥，监听 443 端口；HTTP 监听 80 端口并指向同一站点。

**更新** 完善SSL证书配置，包括kotion.top域名的证书文件路径和端口配置。

### 容器化与镜像
- Next.js 应用：
  - 当前 Dockerfile 复制全部源码并执行 npm start，未启用分层构建与只读用户。
  - 建议：在构建阶段生成 dist 并在运行阶段仅复制必要文件，启用只读文件系统与非 root 用户。
- Vite 前端应用：
  - 使用 Nginx 镜像，复制构建产物与 Nginx 配置，暴露 80 端口。
  - 建议：固定镜像版本、最小化权限、启用健康检查。
- **独立 room-server**：
  - 使用 Node.js 22 Alpine 基础镜像，安装生产依赖后复制源码。
  - 默认暴露端口 1234，支持环境变量配置。
  - CMD 启动 node ./src/server.mjs。
  - **SSL支持**：内置SSL配置，支持通过环境变量启用并加载证书文件。
- **Electron 桌面应用**：

## 故障排除指南
- 协作编辑服务无法连接数据库
  - 检查数据库主机、端口、用户名、密码与数据库名是否正确。
  - 观察日志中 ping 错误与重连行为，确认网络连通性。
  - **独立 room-server 模式**：检查 room-server 的数据库连接配置，确认端口 1234 是否可达。
- WebSocket 无法升级
  - 确认 Nginx 中已启用代理头透传与 HTTP/1.1 代理版本。
  - 检查后端服务端口与防火墙策略。
  - **部署模式差异**：确认使用的是独立 room-server 还是传统 editor 服务的端口配置。
  - **URL变更**：确认WebSocket服务器URL已从localhost:3000更新为kotion.top:1234。
- 前端代理失败
  - 确认 Vite 开发代理的目标地址与路径重写规则。
  - 若使用 HTTPS，确保 secure 选项与证书校验符合预期。
- Docker 镜像启动异常
  - Next.js 应用建议改为构建产物运行，避免复制源码带来的体积与安全风险。
  - Vite 应用建议固定 Nginx 版本并检查配置文件挂载权限。
  - **独立 room-server**：检查容器端口映射（1234:1234），确认环境变量配置正确。
  - **SSL证书**：确认SSL证书文件已正确挂载到容器中。
- **Electron 桌面应用特有问题**
  - 自定义协议无法加载：检查 app:// 协议注册和文件路径映射
  - IPC 通信失败：确认 contextBridge 配置和 API 暴露
  - 本地数据库连接问题：检查 SQLite 文件权限和路径
  - 打包失败：确认 electron-builder 配置和平台依赖
- **独立 room-server 特有问题**
  - 服务无法启动：检查 NODE_ENV 和 PORT 环境变量配置。
  - 数据库连接失败：确认 MySQL 服务可达，检查连接参数。
  - Redis 连接问题：验证 Redis 服务状态和认证配置。
  - **SSL配置问题**：检查SSL_ENABLED环境变量和证书路径配置。

### 部署场景与配置建议

#### 云服务器部署
- 前端：使用 Nginx 容器承载静态资源与反向代理，挂载证书与配置文件。

- 安全：仅开放 80/443，内网访问数据库与缓存；启用 WAF 与 DDOS 防护。

#### 容器集群部署（Kubernetes）
- 前端：Deployment + Ingress，配置 TLS 证书与健康检查。
- 后端：Deployment + Service，使用 ConfigMap/Secret 注入环境变量。
- **独立 room-server 集群**：可为 room-server 创建专用的 Deployment 和 Service，支持水平扩展。
- **桌面应用部署**：桌面应用不适合容器化部署，建议提供原生安装包。
- 存储：数据库与缓存使用托管服务或 StatefulSet。

#### 本地开发环境
- 使用 Vite 开发代理将 /api 指向本地或远程 Nginx。
- Next.js 应用可直接运行，或在本地容器中验证构建产物。
- **独立 room-server 开发**：可单独启动 room-server 进行开发调试，使用不同的端口避免冲突。
